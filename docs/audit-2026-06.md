# Repository Audit — June 2026

Full audit of the HyprDeck workspace (~15.6k lines of Rust across four crates)
covering four dimensions: documentation vs. real implementation, redundancy,
stale or erroneous comments, and half-wired features.  Every finding below was
verified directly against the source at the time of the audit.

Findings are labelled (A1, B2, …) and cross-referenced by the remediation
work that landed alongside this report.

### Deferred follow-ups

- **`icons` lunar render mode**: themes ship only `theme.toml` — there is no
  theme asset-path schema, no asset plumbing into `ThemeContext`, no
  binary-asset extraction from `include_dir`-embedded themes, and no shipped
  artwork.  The decode/draw primitives (`image` crate,
  `render_utils::draw_image`) already exist, so nothing is saved by rushing
  it.  Selecting it warns once and falls back to canvas.
- **Scroll events**: `PointerEventKind::Axis` is only logged in `main.rs`, so
  the `sound` module's `Scroll` handler is dead for the same reason KeyPress
  was.  The Axis event carries a position, so the existing pointer hit-test
  path can serve it; tracked as a follow-up.
- **Key repeat / key release**: keyboard wiring delivers press events only;
  `release_key` is a no-op and repeat is not requested from SCTK.
- **`DodgeActive`** needs active-window tracking in `panel.rs` before it can
  do anything; until then it behaves like a permanently visible panel.
