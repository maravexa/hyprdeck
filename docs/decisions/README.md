# Architecture decision records

Use an ADR to record a prospective, durable technical decision that affects the project beyond a single implementation change.

- Create a new dated, descriptive Markdown file from [the template](template.md).
- Record the context, decision, consequences, and status before or with the change.
- Keep the record factual and concise; link to source, issues, or pull requests only when they provide necessary context.
- Do not retrofit ADRs for routine changes or historical narration.
- Do not rewrite an accepted decision; supersede it with a new ADR when the decision changes.
